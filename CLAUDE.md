# a-personal-assistant

A personal assistant built on OpenClaw. Uses OpenClaw's browser automation and skills system; current capabilities include automating Ripio exchange operations (DCA / login / buy).

## Project Structure

- `bootstrap.sh` — One-shot macOS installer: Homebrew, Node, Docker Desktop, Playwright, `.env`, then `docker compose up -d`. Idempotent.
- `skills/` — OpenClaw skills bundled into the image and auto-synced into the container by the entrypoint on each start
  - `_template/` — skeleton for new skills, with reusable helpers (`fill_by_id`, `click_by_id`, `wait_for_url_stable`) in `scripts/_template.sh`
  - `ripio-login/` — Automated Ripio login flow (email/password + 2FA + magic link)
  - `ripio-buy/` — Single buy action: buys the configured asset with the max available balance. Assumes logged in.
  - `ripio-dca/` — Orchestrator (markdown only): invokes `ripio-login` then `ripio-buy` for the full DCA flow.
- `docs/LEGACY_recording-a-skill.md` — Contributor walkthrough: Playwright codegen → LLM translation → installed skill (legacy doc; still mostly accurate, slated for refresh)
- `prompts/skill-from-codegen.md` — The templated LLM prompt used by the workflow above; encodes every skill convention this repo follows
- `Dockerfile` + `a-personal-assistant-entrypoint.sh` — self-contained image (published to `ghcr.io/cristianperez06/a-personal-assistant:latest`) that bundles OpenClaw, Chromium, and this repo's skills.
- `docker-compose.yml` — runs the published image with the right volumes and env-var wiring.
- `LEGACY_README.md`, `LEGACY_openclaw-instructions.md`, `LEGACY_openclaw-docker-instructions.md` — previous developer-only docs. Kept temporarily as reference while the new flow stabilises; remove once nothing references them.

## Running the gateway

```bash
# First-time setup (installs everything + starts the container)
./bootstrap.sh

# Subsequent runs
docker compose up -d
docker compose down
```

Dashboard: http://localhost:18789/. The pairing token is in `.env` as `OPENCLAW_GATEWAY_TOKEN`.

## Deploying skills

Skills under `skills/` are baked into the Docker image and copied into the running container's workspace by the entrypoint (`a-personal-assistant-entrypoint.sh`) on every start. To pick up local edits without rebuilding the image:

```bash
docker cp skills/<skill-name> a-personal-assistant:/home/node/.openclaw/workspace/skills/
```

The container picks up changes on the next skill invocation; no restart needed.

## Running CLI commands inside the container

```bash
docker compose exec a-personal-assistant node dist/index.js <command>
```

## Environment Variables

Defined in `.env` (see `.env.example`). `bootstrap.sh` walks the user through these interactively. Key vars:

- `OPENCLAW_GATEWAY_TOKEN` — dashboard pairing token (auto-generated by bootstrap)
- `LLM_API_KEY` / `LLM_MODEL` — provider credentials, e.g. `openai/gpt-5`
- `TELEGRAM_BOT_TOKEN` — optional; without it the Telegram pathway is disabled but the dashboard still works
- `RIPIO_EMAIL`, `RIPIO_PASSWORD`, `RIPIO_DCA_ASSET_ORIGIN`, `RIPIO_DCA_ASSET_TARGET` — optional, used by the Ripio skills

## Contributing a New Skill

When a user asks for help adding a new automation (or a non-dev contributor asks how to add one), route them through the documented workflow rather than hand-writing the skill from scratch:

1. Point them at `docs/LEGACY_recording-a-skill.md` for the end-to-end walkthrough.
2. The translation step is the `/skill-from-codegen` Claude Code skill (`.claude/skills/skill-from-codegen/`) — it gathers context, maps `REPLACE_WITH_*` placeholders to `<SHORT_SKILL_NAME>__<SUFFIX>` env vars, and writes the SKILL.md + bash script. It already encodes every convention this repo follows (frontmatter shape, exit-code conventions, the React-safe `fill_by_id` pattern, `Failure Handling` boilerplate, etc.). Invoke it instead of paraphrasing.
3. New skills should start from `skills/_template/` (copy the directory, rename, fill in placeholders) so they pick up the helper functions without copy-paste drift.

If you're authoring a skill directly (without the codegen workflow), still follow `skills/_template/` and the conventions documented in the `/skill-from-codegen` skill — they're load-bearing for the agent's ability to invoke skills correctly.

## Development Notes

- For local development without Docker, run `openclaw gateway run` directly on the host (avoids origin/networking issues).
- Docker deployment requires `gateway.controlUi.allowedOrigins` to be configured. See `LEGACY_openclaw-instructions.md` for the original notes.
- Browser automation uses the Chromium baked into the image. Host-side Playwright (installed by `bootstrap.sh`) is only used for skill *authoring* via `npx playwright codegen`.
